Claim lifecycle

Core

New: priority-range claims, started_at + timeout_at on start, timeout failures, death recovery.

stateDiagram-v2
    direction TB
    Ready --> Claimed : claim within priority range
    Claimed --> Running : start sets started_at, timeout_at
    Running --> Finished : perform returns
    Running --> Failed : perform raises
    Running --> Failed : max_run_time reached
    Running --> Failed : watchdog sweep past timeout_at
    Claimed --> Failed : process died
    Failed --> Ready : death recovery, attempts below cap
    Claimed --> Ready : graceful release before start

delayed_job run and retry

Shim

delayed_job semantics on Active Job: 25 attempts, attempts**4 + 5 back-off, hooks, destroy_failed_jobs.

stateDiagram-v2
    direction TB
    [*] --> Enqueued : enqueue hook
    Enqueued --> Running : before hook
    Running --> Succeeded : success, after hooks
    Running --> Rescheduled : error hook, attempts below max_attempts
    Rescheduled --> Enqueued : run_at = reschedule_at(now, attempts)
    Running --> Kept : failure hook, destroy_failed_jobs false
    Running --> Removed : failure hook, destroy_failed_jobs true
    Succeeded --> [*]
    Kept --> [*]
    Removed --> [*]

Drain mode and work_off

Core

jobs:workoff and --exit-on-complete stop once nothing is ready or due in the worker's queues and priority range.

stateDiagram-v2
    direction TB
    [*] --> Polling
    Polling --> Performing : claimed jobs
    Performing --> Polling : pool has capacity
    Polling --> Checking : nothing claimed
    Checking --> Polling : ready or due jobs remain
    Checking --> Drained : none remain, pool idle
    Drained --> [*] : drained.solid_queue, supervisor stops
